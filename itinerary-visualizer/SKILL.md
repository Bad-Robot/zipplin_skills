# 行程可视化

把文字行程整理成结构化数据，核实地点与道路，再生成可离线打开、可打印、可按天浏览的行程网页。成品中的地图位置、方向和路线来自坐标与道路数据；手绘只改变视觉表现，不改变地理关系。

## 工作流

1. 阅读用户提供的行程，提取日期、每日顺序、活动、住宿、用餐、提示和图片线索。不要擅自增删目的地。
2. 按 [行程数据规范](references/itinerary-schema.md) 创建 UTF-8 JSON。先保留用户原文，再把路线拆成每日有序 `stops`。
3. 核实同名地点。优先使用景区入口、停车场、酒店或车站的精确地址，而不是行政区中心。把检索到的名称、完整地址和 GCJ-02 坐标写入 JSON。
4. 正式自驾地图必须使用道路服务返回的 polyline、里程和时间。若环境中存在 `AMAP_WEB_KEY` 或 `AMAP_KEY`，构建脚本会补齐缺失坐标和驾车路线；不得把 Key 写进 JSON、HTML、截图或日志。
5. 主动搜索并视觉核实代表性景点的实景照片，记录来源、作者、许可，下载后写入 `gallery`；没有照片不能用插画兜底。为代表性地点补充 `motif`、`scenery` 和可选的 `scenery_image`。图像只作为地点特色意象，地点锚点仍由坐标决定。选择方法见 [地图与素材工作流](references/map-and-assets.md)。
6. 生成网页：

   ```bash
   python3 scripts/build_itinerary.py --input /absolute/path/itinerary.json --output /absolute/path/output-dir --require-complete
   ```

   需要先查看版式但尚无地图服务时，可去掉 `--require-complete`。脚本会把直线估算明确标成“预览估算”，这种结果不能作为正式地图交付。
7. 正式构建会要求真实路线、每日地理底图和带来源的实景照片。有 Key 自动获取底图，无 Key 可提供带配准参数的离线底图。打开生成的 `index.html`，验证桌面和手机布局、每个日期按钮、自动居中、拖拽缩放、距离列表、住宿标记、灯箱、打印与复制功能。
8. 最终说明数据来源、坐标系、查询日期、近似项和路线不替代实时导航。真实地图的验收条件见 [质量检查表](references/quality-checklist.md)。

## 生成规则

- 以路线 polyline 和地点坐标作为唯一几何真相。不要为排版移动地点、拉直路线或按图片位置重排城市。
- 地图使用墨卡托投影；同一输出中的 POI 与路线必须采用同一坐标系。高德数据使用 GCJ-02。
- 每日卡片必须列出“地点 A → 地点 B · 公里数 · 预计时间”，因为地图标签可能被图片或标记遮挡。
- 页首完整显示地图。地图吸顶后保持高:宽约 2:3，可拖动查看被裁切区域；切换日期时按该日全部路线边界自动居中。
- 住宿使用独立的蓝色床位标记，并随当天路线高亮。
- 每日正文只使用实景照片，桌面和手机均为单行横滑，置于时间轴之前；点击打开含来源署名的灯箱。手绘意象只能进入地图装饰层。
- 默认采用紧凑橙红页首、米色背景、白色单列卡片、真实底图加纸感显示。具体样式见 [视觉与模块说明](references/visual-system.md)。
- 输出保持单文件可用：地图、结构化数据与本地图片嵌入 HTML；同时保留 `map.svg` 和 `itinerary.resolved.json` 方便复核。

## 输入不足时

能从上下文可靠推断的字段直接补齐。只有地点重名会改变路线、缺失的交通方式会改变规划接口时，才提出一个简短问题。日期、预算和酒店未提供时可省略对应模块，不阻塞地图生成。

## 附带资源

- `scripts/build_itinerary.py`：校验数据、可选调用高德、绘制手绘 SVG、生成单页网页。
- `scripts/basemap.py`：底图获取、Mercator 配准与参数验证。
- `assets/itinerary-style.css`：经用户确认的默认样式，生成时内联。
- `scripts/test_browser.cjs`：响应式、图集与地图交互回归。
- `scripts/test_skill.py`：离线端到端验证。
- `assets/itinerary-template.html`：响应式交互页面模板。
- `assets/example-itinerary.json`：最小可运行示例。
