# 地图与素材工作流

## 地点与路线

高德 Web 服务的调用顺序：

1. 关键词 POI 搜索，结合 `region` 限定城市或行政区。
2. POI 没有合适结果时使用地址地理编码。
3. 景区优先入口坐标；城市停靠点使用酒店、车站、广场或停车场等可导航位置。
4. 相邻 stops 调用驾车路线，保存首选路线的完整 polyline、距离和预计时间。

构建脚本识别 `AMAP_WEB_KEY` 和 `AMAP_KEY`。Key 只通过环境变量读取。高德 POI 与道路坐标都是 GCJ-02；如叠加 OSM 数据，先把 WGS84 转为 GCJ-02，且必须保留 OSM 署名。

路线数据会变化。正式输出应填写 `route_queried_at`，并在出发前用导航应用复核封路、边防公路、景区内部交通和节假日拥堵。

## 地方特色与图片

地图装饰选择少量能识别地点的意象，例如草原河曲、森林或地方建筑，可采用原创插画并标注为特色意象。正文图集独立搜索真实摄影，不采用插画兜底，详见下方实景优先规则。

不要抓取地图平台评论区照片后直接打包进网页。不要把生成插画描述为现场实景。地图景物卡最多保留 6–8 个，避免遮挡路线；正文图片组仅放实景照片。

## 手绘而不失真

- 不使用几何位移滤镜；仅改变底图配色并叠加纸纹。
- 图片卡可沿地图边缘布局并用虚线连接实际地点。
- 路线始终绘制在景物卡之上，使用白色衬底保证可读性。
- 公里标签取真实路线 polyline 的几何中点，必要时只做小幅垂直偏移。
- 景物大小不是比例尺的一部分；页面数据说明中必须明确这一点。


## 实景优先规则（替代上面的插画兜底顺序）

用户只提供文字时，主动搜索实景照片，不要求用户先提供来源。优先 Wikimedia Commons 有明确许可的照片、用户许可素材、可合法引用的官方照片。先查看图片，核对城市、景点、现代／历史照片、视角和季节，再下载已选素材到本地。保留作者、来源页与许可。不要依赖会失效的远程热链。没有可靠照片时继续检索或明确报告缺项，不能自动生成插画占位后交付。地图的 `scenery_image` 与正文 `gallery` 是两个独立通道。

## 底图配准

优先使用同为 GCJ-02 的高德静态底图，每日根据所有路线点、POI 和住宿拟合范围。使用 `scripts/basemap.py` 的投影函数，不再对路线独立做 min/max 拉伸。v3/staticmap 在当前 scale=2 请求下，tile_size=512；下载的图像宽高为请求的两倍，叠加坐标仍按请求逻辑像素计算。不能误用 256，也不能重复乘 scale。

把中心经纬度、zoom、请求 width/height、tile_size、scale、来源和日期与图片一起缓存。使用至少三个分散 POI 校验底图落点，并目视确认路线贴合道路；更换服务或比例参数时重新校准。配色滤镜只应用底图，不作用照片或几何位置。底图原始/纸感切换不更换坐标。
